大模型里的“位置嵌入/位置编码”，本质是在解决一个问题：**自注意力本身不知道顺序**。  
如果只给 Transformer 一堆 token embedding，把句子顺序打乱，注意力算出来的结果也只是跟着换位置，模型无法知道“谁在前、谁在后、相距多远”。所以必须把位置信息注入进去。

下面按主流方案解读。

---

## 1. 为什么自注意力需要位置信息？

自注意力的核心是：

\[
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^T}{\sqrt d}\right)V
\]

它计算的是 token 两两之间的相似度。这个操作对输入顺序是**置换等变**的：你交换输入 token 的顺序，输出也只是跟着交换，模型内部没有“第 1 个、第 2 个”的概念。

因此需要位置编码，让模型区分：

- “猫追狗”和“狗追猫”
- “A 在 B 左边”和“A 在 B 右边”
- 距离远近、局部依赖、长距离依赖

---

## 2. 绝对位置编码：最直观的方案

最早 Transformer 用绝对位置编码。做法是：

\[
x_i = \text{TokenEmbed}(w_i) + \text{PosEmbed}(i)
\]

也就是把第 \(i\) 个位置的向量加到 token 向量上。

### 2.1 可学习位置嵌入

BERT、GPT-2、GPT-3 早期常用这种方式：

\[
P \in \mathbb{R}^{L_{\max}\times d}
\]

每个位置有一个可训练向量。优点是简单、表达能力强；缺点是：

- 最大长度固定，超过训练长度就不能直接外推；
- 位置参数随长度增长；
- 长上下文扩展麻烦。

### 2.2 正弦余弦位置编码

原始 Transformer 用固定公式：

\[
PE(pos,2i)=\sin\left(\frac{pos}{10000^{2i/d}}\right)
\]

\[
PE(pos,2i+1)=\cos\left(\frac{pos}{10000^{2i/d}}\right)
\]

不同维度对应不同频率。低频维度变化慢，高频维度变化快。它有一个好性质：位置 \(pos+k\) 的编码可以看成位置 \(pos\) 编码的线性旋转，因此注意力理论上能学到相对位置关系。

但实际中，加性绝对编码外推能力也有限，因为模型训练时只见过有限位置。

---

## 3. 相对位置编码：直接建模“相距多远”

相对位置编码不关心绝对位置，而关心 token 之间的相对距离 \(i-j\)。

典型做法是在注意力分数上加一个偏置：

\[
e_{ij}=\frac{q_i k_j^T}{\sqrt d}+b_{i-j}
\]

比如 T5 使用相对位置 bias：把相对距离分桶，近的距离精确表示，远的距离对数分桶，然后每个桶学一个标量偏置。

优点是更符合语言直觉：很多语法关系取决于相对距离，而不是绝对位置。  
缺点是实现比绝对编码复杂，有些方案不能完全预计算 KV cache。

---

## 4. RoPE：当前大模型主流位置编码

LLaMA、Qwen、Mistral 等主流大模型普遍使用 **RoPE，旋转位置编码**。

RoPE 的核心思想很漂亮：  
**不把位置向量加到 embedding 上，而是在注意力计算时，把 Q 和 K 向量按位置旋转。**

### 4.1 二维旋转直觉

对于二维向量 \((x_1,x_2)\)，旋转矩阵是：

\[
R(\theta)=
\begin{bmatrix}
\cos\theta & -\sin\theta\\
\sin\theta & \cos\theta
\end{bmatrix}
\]

假设位置 \(m\) 的 query 是 \(q_m\)，位置 \(n\) 的 key 是 \(k_n\)。RoPE 做：

\[
q_m = R(m\theta)q
\]

\[
k_n = R(n\theta)k
\]

那么它们的点积：

\[
q_m^T k_n
= q^T R(m\theta)^T R(n\theta) k
= q^T R((n-m)\theta) k
\]

结果只依赖相对位置 \(n-m\)，而不是绝对位置 \(m,n\)。  
这就是 RoPE 的关键：**用绝对位置的旋转，实现了相对位置的注意力。**

### 4.2 多维怎么处理？

实际 head dimension 通常是 64、128。RoPE 把维度分成很多二维子空间，每一对维度用一个不同频率旋转：

\[
\theta_i = 10000^{-2i/d}
\]

位置 \(m\) 会让第 \(i\) 对维度旋转角度 \(m\theta_i\)。  
高频维度对近距离敏感，低频维度对远距离敏感。

### 4.3 RoPE 的优点

- 不增加位置 embedding 参数；
- 注意力天然依赖相对位置；
- 与 KV cache 兼容好；
- 多频率设计能表达不同尺度位置关系；
- 可以通过插值、改 base 等方式扩展长上下文。

缺点是：训练长度之外的外推不是天然无限好，需要 Position Interpolation、NTK-aware、YaRN 等技术。

---

## 5. ALiBi：另一种外推友好的方案

ALiBi 不在输入加位置嵌入，而是在注意力 logits 上加一个线性惩罚：

\[
\text{score}_{ij} \mathrel{+}= -m_h \cdot (i-j)
\]

其中 \(m_h\) 是每个注意力头不同的斜率。距离越远，惩罚越大。  
它的直觉是：越远的 token 默认越不重要，除非内容特别相关。

优点是：

- 无位置嵌入参数；
- 训练短序列，外推到长序列效果较好；
- 实现简单。

BLOOM 等模型使用过 ALiBi。  
缺点是表达方式比 RoPE 简单，某些任务上不如 RoPE 灵活。

---

## 6. 长上下文扩展：位置编码是核心瓶颈

大模型想从 4K 扩展到 32K、128K，位置编码是关键。常见方法：

- **Position Interpolation**：把超出训练长度的位置索引压缩回训练范围；
- **NTK-aware scaling**：调整 RoPE 的 base 频率，让不同频率不同缩放；
- **YaRN**：结合 NTK、注意力温度缩放等，提升长上下文外推；
- **动态 NTK**：根据输入长度动态调整。

这些方法本质上都是在解决：  
模型训练时只见过有限位置，推理时突然来了更长位置，RoPE 角度分布变了，注意力会失稳。

---

## 7. 总结

大模型位置嵌入的演化可以概括为：

1. **绝对位置嵌入**：把位置向量加到 token embedding 上，简单但外推差。
2. **相对位置编码**：直接建模 token 间距离，更符合注意力机制。
3. **RoPE**：在 Q/K 上做位置旋转，使点积只依赖相对位置，成为当前主流。
4. **ALiBi**：用距离线性偏置，简单且外推友好。
5. **长上下文扩展**：通过插值、NTK、YaRN 等改造 RoPE，实现更长上下文。

一句话：  
**位置嵌入的目的，是让本来“无序”的自注意力拥有顺序感；而 RoPE 之所以成为大模型主流，是因为它用旋转优雅地把绝对位置变成了注意力中的相对位置。**
